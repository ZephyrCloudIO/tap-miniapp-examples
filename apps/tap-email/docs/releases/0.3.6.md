# TAP Email 0.3.6

This patch release implements a focused set of correctness fixes from the [September 27 review](../../../../research/tap-email-deep-review-2026-09-27.md). It retains SDK **0.19.0** and requires TAP host **2.24.1 or later**, which supports the package's header-credential remote MCP declaration.

## Changed behavior

- **Workflow permission:** the surface, permission catalog, owner level and Test Lab inventory use `workflows.read`, matching the host's run-observation action.
- **Operational Zero:** a due reminder prevents all-clear in both in-memory and whole-replica summaries, including reminders outside the visible mail window. Future reminders remain non-actionable until due.
- **Searchable previews:** metadata refreshes preserve previously read body text at the same provider revision. A newer revision can invalidate the previous text and cached body.
- **Sender search:** `from:` matches actual message senders. An address that appears only as a recipient or unclassified participant no longer matches.
- **Canonical tasks:** priority and reminder due date are part of the receipt-backed create operation. Receipt replay returns the existing task reference without a second update that could overwrite later human edits. Existing task identities are preserved; this release does not retroactively change legacy tasks' fields.
- **Release identity:** package, manifest, specialist and email-operations skill are consistently versioned **0.3.6**.

## Review and roadmap

The [32-item capability plan](../../../../docs/plans/tap-email-capability-plan-2026-09-27.md) maps all 60 reviewed Superhuman claims to concrete work or explicit deferral. Its reports describe the inspected **0.3.5 / f3fa6b4** baseline; this release note records the subsequent implementation changes.

This release closes review findings F03, F04 and F06, the permission portion of F05, the sender-filter portion of F08, and the atomic task-creation portion of EP10. It does **not** close the entire first delivery gate. Historical MCP body hydration/pagination, complete workflow inputs and rendered results, reply-recipient resolution, reminder effect/receipt replay, semantic-index maintenance and the broader AI workflows remain planned work.

## Validation

Regression coverage exercises same-revision metadata refresh followed by a real SQLite search, newer-revision invalidation, an overdue reminder outside the loaded window, sender-versus-recipient filtering, and task receipt replay without configuration writes.

Verified locally: **499 Email tests passed**; Email and TAP typechecks passed; SDK manifest validation and repository-wide static Test Lab validation passed; preview, desktop and QuickJS builds passed with package, MCP/activity ABI, React runtime and source-map verification. The production-origin artifact guard also passed.

Local package validation does not prove authenticated installed-host MCP or provider execution. This PR prepares the version; opening it does not publish or deploy it.
