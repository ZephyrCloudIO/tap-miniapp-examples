# TAP Email 0.3.8

This maintenance release accompanies the production sync-monitor correction. Package, manifest, specialist and packaged email-operations skill advance together to **0.3.8**. SDK **0.19.0** and minimum TAP host **2.24.1** remain supported.

## Changed behavior

- Cloudflare's unknown sync queue age remains a visible telemetry warning when independent durable sync checks pass. Missing age alone no longer opens a mailbox-outage alert.
- Known stale backlog, inactive delivery, missing routes, unrecovered application failures, dead-letter backlog and unavailable checks still fail the monitor.
- Recovered history-page failures require a later applied delivery for the same profile/account/page/generation, an advanced checkpoint and a traversal that predates the failed delivery. Failure audit records and coverage counters remain intact.
- Monitor reports preserve raw queue metrics and distinguish incomplete telemetry from measured recovery.

## Release scope and rollout

The client behavior and tool capabilities are carried forward from 0.3.7. The monitoring correction runs in the scheduled GitHub workflow after merge; installing the miniapp does not control that workflow. Changes under `apps/tap-email` also trigger the existing production package build and publication workflow on main.

No new coordinator migration is required. Historical body coverage, semantic-index completeness and Chloe's credential/grant setup still require the acceptance checks documented in [0.3.7](0.3.7.md). A healthy sync monitor does not establish those capabilities as complete.

## Validation

The monitor change passed 238 coordinator tests, 48 Node/static tests, repository static Test Lab verification and read-only production checks. Release validation checks consistent version identities and builds/verifies the preview, desktop and QuickJS package, including integrity, MCP/activity ABI, React runtime, diagnostics and production-origin checks.
